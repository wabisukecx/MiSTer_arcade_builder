# 公開前チェック

## 公開する内容

コード、人工的なデータを使うテスト、README、ライセンス、変更履歴、確認・公開手順、GitHub用設定を公開します。ROM・BIOS・MRA・DAT・CHD・コア・プール・DB・接続情報は含めません。

## 公開方針

問い合わせ、不具合報告、修正・機能追加の依頼、プルリクエストは受け付けません。必要な改変は各自のフォークで行う方針をREADMEに記載します。問い合わせを募集するフォームや連絡先を追加しないでください。公開先ではIssuesとDiscussionsを無効にしてください。READMEへの方針の記載だけではGitHub側の機能は無効になりません。

## ファイルと履歴

- git status --short、git ls-filesで現在の追跡対象を確認。
- git log --all --name-only --format=で履歴のファイル名を確認し、過去の設定やログがあれば内容も確認。
- コミットの作者・コミッターのメールアドレスが公開してよいものか確認。
- スクリーンショットとログのIP、ユーザー名、パスワード、トークン、個人フォルダー名を伏せる。
- Releases用アーカイブは、.local-workや個人設定を含まない配布用フォルダーから作る。実行中の作業フォルダーを丸ごと圧縮しない。

.gitignoreは既存の履歴を消しません。秘密情報が含まれていた場合の処理は[GitHubの案内](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)を参照してください。コミット作者情報を変更するために、既存履歴を無断で書き換えないでください。

## インストールと動作

- 新しいフォルダーへ公開予定ファイルを取得し、READMEの手順でインストール・起動。
- 全自動テストとGitHub Actionsの結果を確認。
- 実機の確認範囲を[TESTING.md](TESTING.md)に記録。
- [既知の制限](KNOWN_LIMITATIONS.md)と削除動作の説明が現在の実装と一致することを確認。
- タグ・パッケージの版・変更履歴を揃え、Release本文に確認済み環境と制限を記載。

## ライセンスと外部データ

コードと文書のライセンスはGPL-3.0-onlyです。外部データのライセンスを変更するものではありません。実行ファイルや依存ライブラリを同梱する場合は、それぞれのライセンス文書・著作権表示・ソース提供条件を確認してください。

スクリーンショットを追加する場合はdocs/screenshots/へ保存し、個人情報を除いてREADMEから参照してください。実際の画像がない状態で、架空の動作画面や検証結果を掲載しないでください。
